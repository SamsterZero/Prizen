# Contributing to Prizen

Prizen is containerized and self-hosted. Contributions must preserve local data ownership and
must not require a Prizen-operated cloud service.

## Start here

- Read the [Project Guide](PROJECT.md) for milestones, planning fields, workflow, and definition of
  done.
- Pick an [open issue](https://github.com/SamsterZero/Prizen/issues) from the active
  [roadmap milestone](https://github.com/users/SamsterZero/projects/4).
- Discuss large or security-sensitive changes before implementation.
- Report vulnerabilities through [private security reporting](SECURITY.md).
- Never share credentials, tokens, cookies, database URLs, or personal data.

## Local setup

Install [Bun](https://bun.sh/) and Docker Compose or Podman Compose.

```sh
bun install
cp .env.example .env
```

Replace both secret placeholders in `.env` with different values generated by
`openssl rand -hex 32`. Never commit `.env` or change its encryption key while keeping the same
database.

Start PostgreSQL and SvelteKit:

```sh
docker compose up -d db
bun run db:migrate
bun run dev
```

Open `http://localhost:5173`. Start the tracker in another terminal when testing polling or
notifications:

```sh
APP_URL=http://localhost:5173 bun scripts/tracker.ts
```

To test the complete production-style stack from the current source:

```sh
docker build -t prizen:local .
PRIZEN_IMAGE=prizen:local docker compose -p prizen-source \
  -f compose.release.yaml up -d --wait
```

With Podman:

```sh
systemctl --user enable --now podman.socket
podman build -t docker.io/library/prizen:local .
PRIZEN_IMAGE=docker.io/library/prizen:local podman compose -p prizen-source \
  -f compose.release.yaml up -d --wait
```

Open `http://127.0.0.1:3000`. If that port is occupied, add `PRIZEN_PORT=3001` and
`ORIGIN=http://localhost:3001` before the Compose command. Stop the stack with the same Compose
project and file. Add `--volumes` only when intentionally resetting its database and secrets.

After source changes, rebuild the same image and rerun `up -d --wait --force-recreate` with the same
project name. Compose preserves the database and secrets volumes.

## Make and verify changes

Create a focused branch from `main`, keep it scoped to one issue, and update tests and docs with
the behavior.

```sh
bun run check
bun run test
bun run lint
bun run build
```

Run `bun run test:e2e` for user-facing flows.

For database changes:

```sh
bun run db:generate
bun run db:migrate
```

Review generated SQL. Use `db:push` only for disposable local experiments—never releases,
upgrades, shared databases, or data that must survive.

## Pull requests

- Link the issue with `Closes #<number>` when applicable.
- Describe the change and how it was tested.
- Call out migrations, configuration, stored data, and outbound connections.
- Include screenshots for visible changes.
- Keep unrelated formatting and generated files out of the PR.
